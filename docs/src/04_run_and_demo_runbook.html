Run & Demo Runbook

From a fresh laptop to a running live demo: install, open, build, test, demo, and what to do when something breaks.
Tested on macOS with OpenJDK 27, Maven 3.9.15, Python 3.14. On Windows, replace : with ; in every -cp.

3. Open the project in an IDE

IntelliJ IDEA

  1. File → Open… → select PA1/chocopy-pa1/pom.xml → Open as Project → Trust Project.
  2. Wait for the Maven import. Then Maven tool window → Lifecycle → double-click package. This generates the lexer and parser.
  3. Generated sources appear under target/generated-sources/. Never edit them: edit .jflex/.cup and rebuild.
  4. For the demo: View → Appearance → Presentation Mode, or set the editor font to ≥ 18 pt.

VS Code

  1. File → Open Folder… → PA1/chocopy-pa1. Install "Extension Pack for Java" when it's suggested.
  2. Open a terminal (Terminal → New Terminal) and use the commands below.

4. Build

cd PA1/chocopy-pa1
mvn clean package

What happens: JFlex turns ChocoPy.jflex into ChocoPyLexer.java. CUP turns ChocoPy.cup into ChocoPyParser.java + ChocoPyTokens.java and prints any grammar conflicts (we have none). javac compiles, and the result is target/assignment.jar. The only expected warnings: Terminal "RESERVED"/"UNRECOGNIZED" was declared but never used, which is intentional.

The first build needs the internet

pom.xml uses an open version range for Jackson, so Maven contacts Maven Central. If you get 502 Bad Gateway or a timeout, simply run it again. Once everything is in ~/.m2, you can build offline with mvn -o clean package. Build on the presentation laptop the day before.

If there are syntax errors, the driver prints them as file:line:col: Parse error near token … instead of JSON. Use --out to get the JSON with its errors list anyway.

6. The live demo

Everything is scripted in PA1/demo/demo.sh. It shows each command before running it and waits for Enter (type s + Enter to skip a step).

cd PA1
bash demo/demo.sh

Timing

The full demo takes about 3 minutes. If the talk is already at time, show steps 2, 6 and 7 only (about 1 minute). Steps 1 and 8 can run while you talk.

Fallback plan

  • Build fails at the venue (no network): use mvn -o clean package. If target/ already exists, don't rebuild at all; the demo only needs target/assignment.jar.
  • Laptop/projector problem: present from the PDF. The slides contain the same outputs.
  • A live question ("what happens if…?"): write the snippet to a file and run --pass=s next to --pass=r. That's the most convincing answer there is.

7. Troubleshooting

SymptomCause → fix
Could not find or load main class chocopy.ChocoPyWrong folder or no build yet → cd PA1/chocopy-pa1, run mvn clean package, and check that target/assignment.jar exists.
Same error on WindowsUse ; instead of : in -cp "chocopy-ref.jar;target/assignment.jar".
502 Bad Gateway / Could not resolve dependenciesMaven Central was unreachable → retry, or mvn -o … once the dependencies are cached.
WARNING: Final field … mutated reflectivelyJDK 24+ with Jackson in the provided code. Harmless; ignore it.
Tests fail right after editing .jflex/.cupYou forgot to rebuild. Always mvn clean package after editing, especially after adding a terminal.
CUP reports a shift/reduce or reduce/reduce conflictThe build stops. Read the conflict report: it names the state and both items. Usually a precedence is missing or two error rules overlap.
python3: command not found (Windows)Use python, and run the commands from demo.sh by hand in Git Bash or WSL.
Output is human-readable errors, not JSONExpected when the program has syntax errors. Add --out file.json to get the JSON.
difftest is slowEach file starts two JVMs. It already runs in parallel, so use a smaller corpus for the demo.
