1. The 60-second version (everyone memorises this)

"We built the ChocoPy front-end: a JFlex lexer and a CUP LALR(1) parser that produce the JSON AST. The tests compare our tree with the reference parser's tree down to every line and column, so most of our work was reverse-engineering the reference's location rules. We did that by using the reference as an oracle: we probed it with tiny inputs, and then we built a random program generator and a differential tester that applies the grader's own rule. We pass all 33 samples and our 44 edge cases, and more than 3,000 random programs give identical results. The three hardest problems were emitting several DEDENTs from one line (solved with a yypushback loop), source locations (node position vs grammar-symbol position), and error recovery. For recovery we went beyond the reference: anchored recovery rules plus Bison-style default reductions, measured with a metric we wrote. We also found three bugs in the reference."

4. Concepts each of us must be able to explain in 30 seconds

Lexical states (YYINITIAL, CODE)

JFlex rules can be limited to a state, and yybegin(S) switches state. Our YYINITIAL means "start of a line, indentation not handled yet". CODE means "inside the line".

Longest match, then rule order

JFlex takes the longest possible match. On a tie, the rule written first wins. So classic is an identifier (longer than class), but class alone is the keyword (same length, keyword rule first).

yypushback(n)

Gives the last n matched characters back to the input. We use it twice: to un-read the first character of a line, and to re-scan the whitespace once per DEDENT.

Why indentation needs Java code

Matching INDENT/DEDENT needs a stack (counting), and regular expressions cannot count. So the regex only finds the whitespace, and the stack logic is Java in the action.

LALR(1)

A bottom-up parser with one token of lookahead. It shifts tokens onto a stack and reduces the right-hand side of a rule to its left-hand side. LALR merges LR(1) states with the same core: the tables are smaller, but in rare cases this creates "mysterious" reduce/reduce conflicts (we had none).

Shift/reduce and reduce/reduce conflicts

S/R: in one state the parser could either shift the next token or reduce. Example: a + b · + c. Precedence settles it. R/R: two different reductions are possible. That's a grammar design error (ours came from two error rules, C17).

precedence, nonassoc, %prec

CUP compares the precedence of the rule (its last terminal) with the lookahead token. Higher token → shift, higher rule → reduce. On a tie, left → reduce, right → shift, nonassoc → error (that's how a<b<c fails). %prec UMINUS gives unary minus the precedence of a dummy token.

xleft / xright

For every labelled symbol e, CUP provides exleft/exright: the location of its leftmost and rightmost token. A node spans from the leftmost symbol's xleft to the rightmost symbol's xright.

Node location vs symbol location

The func_def symbol includes its closing DEDENT. The FuncDef node ends at its body. A class ends at its last member's symbol, so it ends at that DEDENT (coverage: method [34,22], class [36,0]).

CUP error recovery

(1) Report the error. (2) Pop states until one can shift error. (3) Shift it. (4) Throw away input tokens until the next 3 (error_sync_size) parse cleanly. (5) Continue. If it reaches EOF without managing that, it gives up.

Default reductions

In a state whose only possible action is one reduction, do it on any lookahead (Bison does this by default). It lets the parser finish a statement before it notices that the next token is wrong. The error position is unchanged.

Desugaring

Turning syntax that is only a convenience into a simpler core form. elif → nested IfStmt in elseBody.

10. Glossary

TermMeaning in our project
Logical vs physical linePhysical = text up to a line break. Logical = a physical line with at least one real token (blank/comment lines are not logical lines).
INDENT / DEDENTTokens the lexer creates from changes in leading whitespace; they work like { and } around a block.
UNRECOGNIZEDDummy token for anything the lexer cannot accept. No grammar rule uses it, so it always causes a syntax error.
RESERVEDPython keywords that ChocoPy forbids as names but never uses (lambda, import, …).
IDSTRINGA string literal whose contents look like an identifier ("Node"). Allowed as a type annotation.
OracleA trusted implementation used to decide the expected output: here, chocopy-ref.jar.
Differential testingRun two implementations on the same input and compare the results.
MutantA valid program with one deliberate defect, used to test error handling.
Anchored recovery ruleAn error rule with tokens after error (e.g. error NEWLINE) that tells CUP where to resume.
Consistent stateAn LR state with exactly one possible action, which is a reduction.
CascadeExtra, misleading errors caused by poor recovery from one real mistake.
